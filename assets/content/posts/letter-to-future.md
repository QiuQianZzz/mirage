打开这个站点的任何一篇文章，它们其实都是一份 **Markdown 文本文件**。这篇就聊聊
为什么用这么"朴素"的方式组织内容。

## 内容就是文件

站点的每一篇文章，都是一个以 `.md` 结尾的纯文本文件，放在 `assets/content/posts/`
目录下。文件开头用一段 `---` 包裹的 YAML 声明标题、日期、标签等信息：

```yaml
---
title: 为什么用 Markdown 管理内容
date: 2026-03-10
tags: [站点, markdown]
---
```

标题下方写正文的 Markdown。构建时由程序扫描目录，把每个文件渲染成页面。

## 好处之一是：易读、易改

Markdown 是纯文本，没有任何私有格式。好处很明显：

- 用任何编辑器都能打开，记事本也行
- 想改点东西，直接编辑文本再保存，无需登录后台
- 配合 `git`，每篇文章的修改历史都能查得到

相比在后台编辑器里排版，纯文本更"透明"，也更好维护。

## 好处之二是：结构简单、好迁移

文件即结构：一个文件是一篇文章，目录就是分类：

```
assets/content/posts/
  hello-mirage.md
  flutter-web-site.md
```

想换框架或搬家，直接拷贝目录就能带走所有内容。数据不绑定在某个平台或某种数据库里。

## 内容怎么变成页面

流程大致是这样：

1. **解析**：读取文件，用 YAML 头拿到标题、日期、标签等元信息；
2. **渲染**：把正文用 Markdown 渲染成页面元素（标题、段落、代码块等都有对应样式）；
3. **生成**：构建时按标签、日期生成列表页，并自动产出 RSS 订阅源。

所以对使用者来说只是写了一篇普通文档，剩下的交给程序去做。

## 小结

用 Markdown 管理内容，本质是把"内容"和"展示"分开：内容用最通用的文件保存，
展示由前端负责。维护成本和迁移成本都低，这也是很多个人站点偏爱这种方式的原因。
